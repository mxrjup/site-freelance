# CLAUDE.md — AI Agent Guidelines

> Command-first instructions for AI coding agents working on this project.

---

## Project Overview

- **Stack:** Next.js (App Router) + Tailwind CSS v4, static export
- **Output:** `out/` directory (pre-rendered HTML/CSS/JS)
- **Deploy:** GitHub Actions → Infomaniak via SSH on `v*.*.*` tags
- **Database:** None. This is a fully static site.

---

## Coding Rules

### Component Model

- **Default to React Server Components.** No `'use client'` unless the component needs `useState`, `useEffect`, event handlers, or browser APIs.
- **Add `'use client'` only** at the top of the file, only when interactivity is required.

### Styling

- **Use Tailwind CSS utility classes exclusively.** Do not write custom CSS unless extending the design system in `globals.css` via `@theme`.
- **Never use inline `style={{}}` props** unless rendering dynamic values that cannot be expressed as Tailwind classes.
- **Dark mode:** Use `dark:` variant classes. The project uses `prefers-color-scheme`.

### Emojis Policy

- **Never use emojis:** Do not use emojis anywhere in the codebase, UI components, comments, or documentation files. Use SVG icons or clean text instead.

### File Structure

```
app/
├── components/     # Reusable UI components
├── globals.css     # Tailwind imports & design tokens
├── layout.js       # Root layout (metadata, fonts)
└── page.js         # Landing page (assembles components)
```

### Naming

- Components: `PascalCase.js` (e.g., `Header.js`, `Features.js`)
- Pages: `page.js` inside route directories
- Keep components in `app/components/`

## Design Rules — Avoid AI-Generated Aesthetics

The site must look like it was designed by a human, not generated by AI. Follow these rules strictly.

### Never do this (common AI red flags)

- **No gradient text.** Never use `bg-gradient-to-r ... bg-clip-text text-transparent`.
- **No floating gradient orbs/blobs.** No decorative blurred circles with `animate-pulse` or `blur-3xl` in backgrounds.
- **No grid pattern overlays.** No CSS background-image grids used as decoration.
- **No pinging/pulsing status dots.** No `animate-ping` on decorative indicators.
- **No excessive `hover:-translate-y-*` on cards.** Cards should not float upward on hover.
- **No `hover:scale-*` on icons or cards.** Subtle scale on buttons is acceptable; scale on content blocks is not.
- **No glassmorphism everywhere.** Avoid `backdrop-blur` on headers and cards unless specifically requested.
- **No `shadow-xl shadow-*/5` glow effects.** Do not add colored shadow glows to elements.
- **No gradient backgrounds on hover.** Cards should not reveal hidden gradient layers on hover.
- **No decorative badges with pinging dots.** (e.g., "Now available -- v1.0" with an animated circle).
- **No over-styled hero sections.** Keep heroes simple: headline, subtitle, one or two plain buttons.
- **No `animate-*` on decorative elements.** Animations should be limited to functional UI feedback (loading spinners, transitions on interactive state changes).
- **No AI-generated images or pictures.** Always use clean SVG placeholders, solid colored blocks, or text placeholders unless explicitly instructed otherwise.

### Do this instead

- **Use flat, solid colors** from the zinc palette for text and borders.
- **Keep hover effects minimal:** `transition-colors` with a simple color shift is enough.
- **Use whitespace generously.** Let the content breathe.
- **Prefer borders over shadows** for visual separation.
- **Keep typography restrained:** two font weights (regular + semibold) cover most needs.
- **Make it look like a real website,** not a template showcase.

## Build Tasks

```bash

npm install

# Run the dev server (http://localhost:3000)
npm run dev

# Lint the codebase
npm run lint

# Build the static export (outputs to out/)
npm run build

# Verify the build output exists
ls -la out/
```

### Static Export Constraints

- **No `getServerSideProps`** or server-only features
- **No API routes** (`app/api/` is not supported with `output: 'export'`)
- **Images must use `unoptimized: true`** (configured in `next.config.mjs`)
- **No `next/headers` or `next/cookies`** in server components

## SEO Rules & Best Practices

All pages created or modified in this project must adhere to strict static site SEO standards:

### 1. Metadata Configuration (`app/layout.js` & Page Metadata)

- **Title Tags:** Define `metadata.title` with concise, keyword-focused titles. Use `title.template` for nested pages.
- **Meta Descriptions:** Every page must specify a compelling `description` (120–160 characters).
- **Canonical URLs:** Ensure `alternates.canonical` is configured.
- **OpenGraph & Twitter:** Define `openGraph` and `twitter` card tags for social sharing.
- **Static Robots & Sitemap:** Keep `app/robots.js` and `app/sitemap.js` configured with `export const dynamic = 'force-static';` so Next.js static export outputs valid `robots.txt` and `sitemap.xml` files.

### 2. Semantic HTML & Content Structure

- **Single `<h1>` per Page:** Exactly one `<h1>` per page (typically inside the Hero section).
- **Heading Hierarchy:** Maintain strict sequential order (`<h1>` → `<h2>` → `<h3>`). Never skip levels for styling.
- **Semantic Elements:** Use `<header>`, `<nav>`, `<main>`, `<section>`, `<article>`, and `<footer>` appropriately.
- **Image & Element Accessibility:** All images must include descriptive `alt` text. Form controls must have associated `<label>` or `aria-label` attributes.

### 3. Performance & Crawlability

- **Static Pre-rendering:** Leverage Next.js static export (`output: 'export'`) for instant page loads.
- **Unique Component IDs:** Maintain unique `id` attributes on key interactive/navigational elements for automated testing and anchor navigation.

## Eco-conception — Priority #1

This is an eco-responsible website. Performance and minimal environmental footprint are the **top priority** for every change.

### Code Weight

- **Zero unused JavaScript.** Every import must be justified. Remove dead code aggressively.
- **Prefer Server Components.** Client components add JS to the bundle. Only use `'use client'` when strictly necessary.
- **No heavy libraries.** Do not add dependencies for things achievable with vanilla JS or CSS. No animation libraries, no icon font libraries, no CSS-in-JS.
- **Inline SVG icons only.** Do not use icon font packs (FontAwesome, Heroicons package, etc.). Copy the SVG markup directly.
- **Minimal fonts.** Load at most 2 font families. Use `font-display: swap` (handled by `next/font`). No decorative fonts.

### Images & Media

- **No images unless explicitly requested.** Use CSS, SVG, or text instead.
- **No autoplay videos.** No background videos. No GIFs.
- **If an image is required:** use modern formats (WebP/AVIF), compress aggressively, specify `width` and `height` attributes, and use lazy loading.

### Performance Targets

- **Google PageSpeed:** Target 100 on both mobile and desktop.
- **EcoIndex:** Target grade A (< 3 requests, < 200 KB transferred, minimal DOM nodes).
- **Bundle size:** The total JS sent to the client should be as close to 0 KB as possible. Every kilobyte must be justified.
- **DOM nodes:** Keep the DOM shallow and minimal. Avoid deeply nested wrapper `<div>` elements.

### Hosting & Infrastructure

- **Infomaniak hosting only.** All production deployments go to Infomaniak servers (100% renewable energy, European data centers).
- **Static export.** The site is pre-rendered at build time (`output: 'export'`). No server runtime, no serverless functions, no API routes.

## Done Criteria

Before declaring any task complete, **always run:**

```bash
npm run format && npm run lint && npm run build
```

A task is **not done** unless:

1. `npm run format` runs without errors (Prettier formatting applied)
2. `npm run lint` passes with zero errors
3. `npm run build` completes successfully and produces the `out/` directory
4. No `'use client'` directives were added unnecessarily
5. All new components use only Tailwind classes for styling
6. Interactive elements have unique, descriptive `id` attributes
7. Zero emojis exist in the updated files or project
8. No AI-aesthetic red flags from the "Design Rules" section above
9. SEO best practices are respected (single h1, proper metadata, alt texts, valid sitemap & robots configuration)
